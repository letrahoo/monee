## 已定口径

依据 `docs/product/mvp-discussion.md`：保留消费与退款两条事件并关联；退款按退款发生日抵减该期支出，展示消费毛额、退款和净额，跨月不无声改写旧月报表。

Go 是规则唯一实现，金额使用整数分。退款不是收入，也不能在原消费金额上直接扣除后丢失退款事件。

## 本轮交付边界

- 在同一账本的普通人民币消费上登记、查看全额或多次部分退款。
- 原交易、退款日期、实际退回金额、账户与关联关系可追溯；累计有效退款不得超过原消费。
- 服务端验证所有者/编辑权限、同账本、类型、日期、币种和金额；只读角色不能登记。
- 保留幂等、版本冲突、分录平衡及 change_log；并发退款也不能超退。
- 报表显示消费毛额、退款和净额；仅退款的月份也必须出现，净支出可以为负。
- 退款与更正/导入撤销的依赖必须显式处理，不能删除原交易后遗留有效退款，不能将原消费改到小于已退款总额。
- KMP 共用登记和明细界面，Web/Mac 实际验收；不在真实账本试写。

原生来源中的退款行仍需保留来源证据。自动匹配、跨来源合并和通用待核实项处理属于后续任务；本轮不得把尚未关联的来源退款自动当作普通收入入账。

## 实现顺序

1. 数据模型和迁移：当前 schema 2 的交易 CHECK 只允许收入/支出，需要设计 schema 3 的显式 refund/原交易关联，保留外键与历史 ID。升级前一致性备份，验证失败可回滚；更新健康、备份恢复的版本校验。只使用合成迁移样本。
2. Go 领域与 API：退款登记/查询，金额和类型限制、幂等及并发、成员授权；纳入账本版本、分录与变更日志。
3. 一致性：月度及分类毛额/退款/净额，跨月数据；原交易更正、撤销/恢复批次的依赖保护。无法安全处理的修改应明确拒绝并解释，不能静默丢失关联。
4. 共享客户端：原消费详情中的退款入口、剩余可退金额、退款列表、明确的跨月说明及异常反馈。不提供伪造演示数据入口。
5. 完整回归：Go race/vet、共享测试、Web/Mac 构建、双端独立账本操作、GitHub CI、独立审查；证据回填 PR 与 Notion 后再按授权合并。

## 验收矩阵

- [ ] 同月消费 100、退款 30：毛额 100、退款 30、净支出 70，收入不增加。
- [ ] 多次退款 30+70：累计 100；任何追加退款拒绝且不产生额外分录。
- [ ] 跨月消费 100/退款 30：原月保持消费 100；退款月显示退款 30、净支出 -30。
- [ ] 零、负数、额外小数、超额、早于消费日期、不支持币种均拒绝。
- [ ] 同请求重试不重复入账；不同内容复用幂等键冲突；并发不超退。
- [ ] 跨账本/非成员/只读/收入目标/不存在或已撤销目标全部拒绝。
- [ ] 有退款依赖时更正和撤销不破坏额度、关联、分录及报表。
- [ ] schema 2 合成数据升级保留交易、来源、身份、权限和审计；快照恢复及旧版本拒绝新库可验证。
- [ ] Web/Mac 保存、刷新、异常、重复操作、跨月和重启一致；真实账本不受影响。

## 风险与当前进度

最大风险是交易表 CHECK 变更及导入撤销依赖。先证明迁移/恢复和领域不变量，再接 UI，不能用界面隐藏代替服务端约束。现有主干没有退款能力；本文件是实施计划，不是交付声明。

### 2026-09-19 数据迁移基础

- 已实现 schema 3：新增 refund 和同账本原交易关联；重建 transactions 表保留历史字段/ID，事务内校验所有外键，失败回滚并恢复外键开关。
- 非空旧版本库升级前生成一致性快照；备份验证失败不执行迁移。备份目录为数据库路径加 `.backup-before-v3-<随机 ID>`，保留供离线回退；不得用旧二进制直接打开新版数据库。
- 统一账本/身份/健康接口版本上限；身份初始化不得将 schema 3 降回 2，恢复工具拒绝高于当前支持版本的快照。
- 合成测试覆盖旧交易/来源/分录/审计、身份/准入/成员/会话、软删除和创建人逐列保留，外键失败回滚、同账本关联和未来版本拒绝。独立审查当前迁移范围无确认 P1/P2。
- 此阶段当时未开放退款写入入口；后续实现见下节，双端实际验收仍是合并前置条件。

### 2026-09-19 退款功能实现

- 专用 GET/POST `transactions/{id}/refunds`：同账本/成员授权、CNY/日期/额度、原消费版本推进、请求幂等和双分录；查询可由退款返回原消费。
- 退款发生月抵减支出，不增加收入；月度和分类返回毛额、退款、净额，只有退款的月份也显示负净支出。
- 有退款时不能将消费改成收入或低于已退款金额；撤销导入保留有关联的原消费。暂不支持单独重分类关联交易，但可改备注；退款沿用原消费分类。
- Web/Mac 共用登记、剩余金额、退款列表与跨月说明；不确定提交的 key/版本/内容由长生命周期 API 按服务/账号/账本保存，页面卸载和导航不丢失。本轮不宣称整页重载或进程退出后还保留未确认请求。
- 自动测试覆盖主规则、并发/独立连接、权限/CSRF/撤权重试、快照恢复；共享测试覆盖请求状态隔离与负额/零额图表。最终 GitHub CI、双端实际操作矩阵尚须完成，不以自动测试替代验收。
