# 同笔消费关联：共享操作面板

基线61a0cd2。此片接入真实Go API，不引入示例数据或合成登录。正常schema5能力门禁及Open6拒绝策略保持不变，因此本片编译不代表正常服务已可操作。

## 入口与边界

- 编辑者从账本“关联同笔消费”进入，明确只在当前页选择两条现有expense并指定主记录；跨页选择留待后续，不猜测主记录。
- 主记录可进入关联详情、查看主/副各自来源及历史状态。只读成员可查看，不能创建或撤回。
- 活跃关联成员在详情提示先撤回；退款、修改金额/分类/备注入口隐藏。Go事务规则仍是权威，不能仅靠UI锁定。
- 从Go预览读取整数金额影响；确认前的版本、两条ID/版本、选择必须仍匹配。账本变化后重新预览。
- 撤回使用详情顶层的当前ledgerVersion及active decisionVersion，不误用receipt历史ledgerVersion。

## 未知结果与退出

API持有scope-bound完整submission。面板切换、关闭或取消不能生成替代key；再次打开从pending恢复原确认/撤回input，只允许核实原请求。明确invalid/conflict后按API结果清pending并刷新。新的服务地址或身份不得接收旧submission；迟到结果不覆盖新选择/详情。

金额保持整数/十进制字符串。双来源读取不抑制副记录、不把source证据合并为一条交易；显示角色、filename、line以保留来源区别。

## 验证与开放条件

纯状态回归及完整Go/shared/Web/Mac检查，独立审查；有权限且工具可用时正常OAuth双端实际操作。没有实际操作证据就明确未验收。下一阶段仍需正常schema6运行门禁和实际旧v5兼容fixture，不可直接提升常量后称交付。
