# 私有离线升级协调器

本增量提供未导出的、无 CLI/HTTP/UI 调用路径的协调函数，仅在隔离合成库测试。生产 SchemaVersion 仍5，正常 Open 仍拒绝非空关联表与版本6；不能在真实库调用本函数后直接启动当前程序。

## 前置条件及顺序

调用者必须已停止全部旧连接，并持有共享目录 Lease。租约不约束任意 SQLite 客户端，这是已验证的限制。

1. 在租约 Within 内规范目录，固定读取 application.db，拒绝非普通源文件。备份名只能是新的同目录子项。
2. 只读事务检查固定版本5、精确关联三表/索引结构、三表全空及无关联决策审计残留。保留该事务直到提交。
3. 用线上已有 Snapshot 生成独立备份。VerifySnapshot 校验 manifest版本、hash、完整性、外键及声明的schema5。
4. 对事务源与备份计算逻辑指纹，比较完整 sqlite_schema、所有表列及所有行（类型标记、行排序、保留重复行）；不能比较 VACUUM 前后的 SQLite 文件字节。指纹仅在内存中，不输出数据。
5. 同步备份数据库、manifest、备份目录和父目录。任何错误拒绝切换；只读回缓存不能替代落盘要求。此处遵循操作系统 Sync 语义，不声称模拟过真实掉电或硬件故障。
6. 同一事务内重验门禁并设置 user_version=6，提交。读取快照建立后若有非协作写者提交，SQLite 升级写事务失败而不是覆盖该写者。错误保留源版本，已经生成的备份不自动删除，供检查。
7. 连接关闭后才退出租约作用域，调用方仍持有租约。返回备份路径；不会自动切路由、恢复或启动服务。

## 局限与后续

- 本函数只建立版本能力切换的原子性与备份前提，没有完整版本6运行能力交付。当前程序明确拒绝其产物，隔离测试后可恢复v5备份。
- 可信且稳定的目录命名空间仍是前提，不防御恶意管理员替换规范目录/备份文件。指纹比较可能占用与逻辑库内容同量级内存，暂不开放大库入口；后续应流式/有界处理。
- 仅支持当前普通 SQLite 应用结构；未知关联 DDL 拒绝，不修复。无资金金额浮点运算；指纹仅按驱动返回值编码数据。
- future版本6正常支持必须同时保留真实旧v5兼容fixture、完整reader/writer覆盖、授权API/共享UI及实际双端验收，不能只是修改生产版本常量解除门禁。
