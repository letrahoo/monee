# 日常账本工作台候选版本

基线：main `72f2a37`；分支 `feat/daily-ledger-workbench`。用户要求持续消费 Notion 看板，直到形成可交付增量。M-09 仍在独立草稿 PR #14 待实际双端验收，不合并、不把其候选代码隐式引入此分支。

## 本批范围与顺序

1. M-35 四 Tab：总览、明细、统计、我的；真实本地 API，暖白/森林绿，高对比辅助文字；保留各 Tab 浏览状态。文件补充与来源历史归我的，手记仅补漏，待核实为轻入口，不作主 Tab 或角标。
2. M-39 年度接口与 M-43 明细筛选：依赖 M-08/M-02 已在 main；12 月精确整数统计、记录月份与无记录区别、稳定账户 ID、组合过滤及稳定分页，筛选不改变月度总计。
3. 接入 M-40 月份面板/12 年网格、M-41 年趋势联动、M-42 分类毛额统一口径、M-36 明细筛选 UI。后端保持唯一财务口径，结余不是余额；缺失记录不伪装来源已完整覆盖。
4. 总览复用已实现月度指标与近期明细。M-22 的完整自动获取/首次使用依赖来源与核实闭环，未就绪前不提供假连接、示例填充或标为完成；本批只交付其已有能力可用的界面。

## 开发与交付边界

- 每步读任务、更新 Notion，开发后完整 Go race/vet、共享 JVM 测试、Web 生产构建、Mac 分发构建、独立审查。一次批次内依赖串联不代表上游已经最终验收；最终候选还需受影响双端实际流程。
- 只用独立合成数据；没有来源样本不得虚构银行格式，没有明确预算不启动付费模型；不扩邮件/原生手机/生产部署。
- 未具备真实登录和正常交互环境时，继续实现其他独立任务，但保留实际操作缺口，不将自动化结果宣布为可正式交付。
- 不直接推 main，不自动合并 PR。候选产物、PR、已验收范围与待验收门槛分开记录。

## 候选验收矩阵

- 正常登录、账本切换/只读/撤权与退出；四 Tab 状态、返回、键盘焦点、窄屏。
- 年/月选择、1900/2200 边界、12 年分页、跨年与仅退款月、无记录与零净额区别。
- 年/月毛额、退款、净额、收入与结余一致；分类金额/占比均毛额，跨月退款另列；退款不计收入。
- 类型/稳定账户/分类/query 组合、清空、同日多页稳定排序与范围提示；筛选不改变全月总计。
- 现有导入/原文/待核实/撤销恢复/退款/纠错回归；未知结果重试不重账。
- 服务/客户端重启持久化、网络错误与恢复，Web/Mac 数据一致；不在含私有资料实例故障注入。
