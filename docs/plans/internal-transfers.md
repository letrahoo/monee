# M-09 本人账户间转账

任务：[Notion M-09](https://app.notion.com/p/3dc0bbfd57ca815eb6a9f1650279d758)。基线：M-08 合并后的 `72f2a37`；分支 `feat/internal-transfers`。状态：进行中，未开放转账写入接口或 UI。

## 范围

- 同一账本、人民币、用户明确确认的本人资金账户之间转移；不是实际执行银行转账。
- 转出和转入账户必须明确且不同，整数分两侧相抵，不计收入、消费或退款；在明细保留金额和方向以供核对。
- 缺失侧不得用“待核实资金账户”猜测补齐。原生导入中的未确认转账继续保留来源与待核实状态，不进入普通收支。
- 独立转账类型及两侧账户/分录，逐请求权限、幂等、事务原子性和审计；重试不重账。
- Web/Mac 共用入口与详情，角色变更、失败/重复、重启及双端汇总一致性实际验收。
- 不扩大到信用卡/白条还款（M-10）、跨来源自动关联（M-11）、手续费自动拆分、跨币种或已核实资产余额。

## 实施顺序与验收

1. 规范输入与资金分录：明确双方账户，严格金额/日期/币种与文本限制，转出负数/转入正数、合计零。
2. 安全迁移与正式落账：增加独立 transfer 类型、双方账户；保留既有退款/来源/审计/身份；升级前备份、失败回滚和恢复测试。先完成持久化及权限/幂等/并发测试，再开放接口。
3. 报表和编辑保护：转账不计收入/毛消费/退款/净消费，仍可查明细；不得走普通收支更正或分类重写而破坏资金分录。
4. API、共享 UI 与完整构建：包括未知结果期间保留原请求，禁止因关闭表单/页面重建生成重复记账。
5. 两端独立合成账本实测：100元A→B不改变收支，双方可查；同账户/缺失账户/零/精度/越界拒绝，重复及断线重试唯一，权限撤销即时生效，导入未知转账仍待核实。
6. 独立审查、GitHub CI和全部实际验收后才合并、回写完成并领取M-10。
