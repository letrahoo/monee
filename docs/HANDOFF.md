## 已定方案与取舍

- 先给产品负责人个人使用，Web / Mac 优先，iOS / Android 后续补齐。
- KMP + Compose Multiplatform 已确定；Web 为 Kotlin/Wasm，Mac 为 JVM/Compose Desktop，不是 WebView 套壳。共用 UI、客户端状态和 API 模型，平台能力分开实现。降低长期开发成本是目标，不能当成已量化验证的收益。
- Go 是账本、去重、分录和统计规则的唯一实现。采用模块化单体，不提前拆微服务。
- 一个本机 Go 服务提供 Web 和 API，Web / Mac 共用 SQLite。后续云端候选为 PostgreSQL，尚未实现远程部署或同步。
- 兼容性优先：稳定 UUID、整数分/字符串金额、实体版本、schema 版本与事务内 change_log；保留这些边界，不把复制数据库当作云端同步。
- 目标来源是支付宝、微信、京东白条及招商、农业、上海银行、工商银行。卡种、格式和脱敏样本仍待确认。
- 希望减少日常人工观察：指定文件夹自动归集优先，邮件附件随后，必要时手动导出补充；手动记账用于补漏。付款后自动记账是需真机验证的后续增强，不是当前承诺。
- 初始超管通过私有配置指定，Google 和 GitHub 分别绑定稳定身份；同一人的两个入口不自动合并为一条身份。白名单成员共同读写当前账本，不是多租户隔离。

## 产品表达原则

MVP 靠可用功能成立，不以页面文字填充未实现的能力。界面只保留操作、结果、错误和影响决策的必要说明。

- 删除账本页宣传段落、Web/Mac/KMP 等实现信息、正常连接横幅、重复的本机保存提示。
- 品牌 Slogan 原文保持 `Know Your Money. Own Your Future.`，仅放登录品牌入口；应用窗口及网页标题为 Monee。
- 格式帮助、数据与隐私、账号 ID/备注、操作记录按需展开；不把内部 actor 标识直接作为操作人名称。
- 保留重复入账确认、不支持交易类型、权限限制和数据保存/备份边界。简化表达不能掩盖财务风险或制造已同步的假象。
- 正式导入页只有空模板；合成示例在测试资料中。功能未实现就不显示占位洞察、伪数据或泛泛建议。

## 已知接续陷阱

- 旧 Mac 进程不会自动加载新构建。当前分支重启后可从钥匙串恢复有效会话；旧版没有该能力。不能从浏览器或文件复制 session token 给它。
- Web 必须由 Go 同源提供；旧静态预览、旧分支和旧浏览器缓存可能显示演示页。先查实际分支、启动目录、监听进程和资源，再判断是否缺功能。
- `connection.json` 包含 baseUrl、instanceId、serviceProtocol；实例身份不是登录凭据。不要恢复旧的共享 token。
- `monee://auth/complete` 只唤起窗口，不作为 Google/GitHub 控制台回调，不带 token，也不接收任意 redirectTo。
- Google service-account JSON 不能用于个人登录。登录授权也不包含读取邮件的权限。
- 新建开发环境可以独立工作；Git 无法恢复原机的密钥、白名单数据库或真实账本，详见运行指南中的私有资料边界。
