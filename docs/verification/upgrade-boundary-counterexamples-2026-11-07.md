# 升级边界反例测试（2026-11-07）

基线 63118d7；仅增加测试与文档，生产 schema 仍为5，没有实际升级器或真实库迁移。

## 已验证的限制

1. 一个在取租约之前已打开、且不遵守租约协议的原生 SQLite 连接，仍可在另一连接把 user_version 从5改为6后写入合成表。同目录第二份协作租约同时明确被拒绝。这证明拿到服务目录锁并提升版本号不足以吊销旧连接，升级前必须关闭所有旧连接。
2. 持租约时在线 Snapshot 仍可成功，且不会释放租约。它只复制数据，既不宣布停机，也不把未来版本当作当前可运行版本。
3. 当前 schema5 的 ledger.Open、auth.Open 和 Restore 拒绝固定版本6。断言只保留原合成表和值、没有新增迁移前备份、Restore不留目标；Check和Snapshot仍可读取/复制版本6。

版本兼容测试固定断言当前 SchemaVersion==5。未来提升生产支持时，必须替换为真实保留的旧v5兼容fixture，不能仅修改一个随常量增长的 SchemaVersion+1。此测试不是已保存的旧二进制兼容证明。

## 检查

两个测试定向 race 连续3次通过。完整 Go race 全部通过（ledger 65.302s），vet/diff-check 通过；fresh 共享测试、Web 生产及 Mac 分发构建通过（1m19s、68任务执行）。独立只读审查未发现 P1/P2。尚待本提交远程 CI；自动检查不替代正常双端操作验收。

## 下一步

显式升级协调必须在受控停机和同一租约下进行精确结构检查、可验证备份、事务内重验及失败回滚；本测试未实现该协调器，也没有解除 schema5 非空关系门禁。尚无正常登录的双端关联验收，不合并、不部署。
