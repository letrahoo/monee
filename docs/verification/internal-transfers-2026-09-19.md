状态：开发实现及本地自动检查通过；双端实际操作验收未完成。分支 `feat/internal-transfers`、[草稿 PR #14](https://github.com/letrahoo/monee/pull/14)，基于 M-08 主干 `72f2a37`。此文所在提交对应本轮实现；不能沿用前置纯函数提交的 CI 作为当前功能证据。

## 实现范围

- CNY 明确本人账户 A→B 的登记，不实际转款；独立 transfer 类型，正数为转账量，不是收入。两侧 clearing 分录相抵，不计收入、消费毛额、退款、净支出或消费分类；两侧账户均可搜索。
- schema4 升级前快照、固定连接事务重建/FK 检查/失败回滚，保留原交易、退款关联、来源、身份与审计。转账只允许修改备注，拒绝普通收支更正、消费退款和分类重写。
- 专用 POST /api/v1/transfers；逐请求授权、Cookie CSRF/Origin、账本隔离、规范化幂等、事务审计/版本。撤权或降为只读后不能重放成功请求。
- 共享登记表单需确认本人账户，明确双方、金额及日期；中性转账金额与方向展示。未确认结果由 API 按服务/用户/账本持有，失败/关闭表单/页面重建保留原请求和 key；不保证整页刷新/进程退出后的 pending 持久化。
- 不包括 M-10 还款、M-11 跨来源匹配、手续费拆分、跨币种和真实资产余额。原生未确认转账仍保留待核实，不自动匹配落账。
