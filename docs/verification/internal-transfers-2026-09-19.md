# M-09 转账验证（基础阶段）

基线 `72f2a37`，分支 `feat/internal-transfers`。当前只有纯 Go 输入规范化和两侧资金分录构造，没有 schema、持久化、API 或 UI。不能合并或称转账可用。

## 本阶段检查

- 转账规范化/金额边界/22类非法输入/普通收支入口拒绝 transfer 的专项 race 测试重复3次通过；补充200字账户、1000字备注及1900/2200/闰年合法边界。
- 全量 Go race/vet、共享 JVM 测试、Web 生产和 Mac 分发构建通过；客户端未改，相关任务复用有效缓存，内置 Go 服务重新构建。
- 独立 Agent 审查未发现确认 P1/P2。两侧金额在1分到1e12分范围相抵，无浮点计算；未明确账户不以占位资金账户补齐。
- 所有用例为内存或临时合成资料；未升级或试写任何真实账本，未部署服务。

## 下一阶段必须验证

- 安全迁移/备份/恢复与旧交易退款关系不变；正式写入使用两个资金账户，不能复用现有资金+分类分录逻辑。
- 报表显式排除 transfer，不可按正负数推断收支；仍保留双方明细。普通分类/更正不能改坏转账结构。
- 逐请求权限、事务失败回滚、幂等、并发和审计，以及后续 API/共享UI。
- Web/Mac 独立合成账本主流程、缺失侧、非法输入、撤权、重试不重账、重启与双端数据一致性；这些尚未实测，构建不能替代。
- 当前提交 GitHub CI 与最终完整功能审查；全部通过后才允许合并。
