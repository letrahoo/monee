# 工作台年度合成夹具与待验收期望

## 范围、格式与使用前提

- 数据文件：[workbench-annual.csv](../../fixtures/synthetic/workbench-annual.csv)。仅用于正常 OAuth 登录后的全新隔离账本，由父任务通过正式「标准 CSV」文件选择、预览、确认导入；不用于真实账本。
- 共 `"15"` 笔普通收支，货币全部 CNY，金额输入均为正数、精确两位小数。支出负号由 Go normalize 产生，不在 CSV 中写负金额。无退款、转账、还款或虚构原生银行格式。
- 表头与 [standard.csv](../../fixtures/synthetic/standard.csv) 一致：`date,type,amount,currency,merchant,category,source,account,external_id,note`。已阅读 [标准解析器](../../server/internal/ingestion/standard_csv.go)、[导入实现](../../server/internal/ledger/import.go) 和 [normalize](../../server/internal/ledger/models.go#L162-L205)，不是猜测格式。
- 唯一来源 `合成工作台标准CSV`，两个资金账户 `合成钱包A`、`合成钱包B`；收入分类为 `工资`、`奖金`，支出分类为 `餐饮`、`学习`、`交通`。商户和备注均明确标记合成。external_id 从 `SYNTH-WB-ANNUAL-001` 至 `SYNTH-WB-ANNUAL-015`，全文件唯一。
- 干净账本首次预览的计划期望：newCount=`"15"`、duplicateCount=`"0"`、similarCount=`"0"`、无错误；确认后 added=`"15"`、skipped=`"0"`。以上是按实现推导，尚未实际导入。
- 同一文件再次导入应命中已提交批次，不新增记录。不要为重复验收改流水号；账本已有其他数据、撤销或退款时，应另行建立对应基线。

## 月度与年度基线（导入后、尚未退款）

## 支出分类毛额顺序

依据 [Go 年度排序](../../server/internal/ledger/annual.go#L114-L129) 与 [月度排序](../../server/internal/ledger/store.go#L381-L391)：grossExpense 降序，同额按分类名升序；分类统计不把收入分类混为支出。以下每项为 `分类: grossExpense`，金额都是 minor 字符串。退款前每类 refund=`"0"`，netExpense 与 grossExpense 相同。

| 期间 | 从前到后的分类毛额 |
|---|---|
| 2025-12 | 餐饮: "1250" |
| 2026-01 | 学习: "2500" → 餐饮: "1500" |
| 2026-09 | 学习: "2000" → 餐饮: "2000" → 交通: "500" |
| 2026-10 | 餐饮: "800" → 交通: "600" → 学习: "400" |
| 2026 全年 | 学习: "4900" → 餐饮: "4300" → 交通: "1100" |
| 空月 | 空列表 |

占比若显示，应以该期间 grossExpense 为分母；九月学习和餐饮占比相同，不要求显示格式或舍入小数位。不能用结余或净支出作为毛额分类占比分母。

## 九月明细 AND 筛选

以下固定月份为 2026-09；账户应从 Go 返回的 filterOptions 选取对应**稳定 accountId**，不能将账户名或 CSV external_id 冒充 API ID。筛选条件间为 AND；query 在 merchant/category/source/account/note 中作不区分大小写的子串查询，不包括 external_id。表内短 ID 是 external_id 的后三位，仅作人工定位。

| 类型 | 账户 | 精确分类 | query | 期望短 ID 集合 | filteredCount |
|---|---|---|---|---|---|
| expense | 合成钱包A | 餐饮 | 咖啡 | 008 | "1" |
| expense | 合成钱包B | 餐饮 | 咖啡 | 009 | "1" |
| expense | 合成钱包A | 学习 | 书店 | 010 | "1" |
| income | 合成钱包B | 奖金 | 九月 | 007 | "1" |
| expense | 合成钱包A | 餐饮 | 书店 | 空 | "0" |
| expense | 不限 | 餐饮 | 咖啡 | 008、009 | "2" |
| refund | 不限 | 不限 | 空 | 空 | "0" |
| 不限 | 不限 | 不限 | 空（清空全部筛选） | 006、007、008、009、010、011 | "6" |

每组筛选只改变明细和 filteredCount；九月全月卡片始终为 income=`"7000"`、grossExpense=`"4500"`、refund=`"0"`、netExpense=`"4500"`、surplus=`"2500"`、totalCount=`"6"`，分类毛额不改变。切换十月后不应夹带九月明细。

同日记录：2026-09-14 有 `"4"` 笔（007–010），2026-10-14 有 `"2"` 笔（013–014）。列表日期应降序，同日按 Go 的 created_at 降序、id 排序，不将 CSV 顺序或 external_id 顺序当作稳定契约；刷新同一账本应稳定。此文件规模不足以触发多页，不能宣称已验证分页边界。

## 退款后变化计划（尚未执行）

退款只能由父任务通过专门退款 API 或真实 UI 从原消费创建；不可往标准 CSV 添加 refund 行或用普通收入代替。先读取原交易真实 ID、最新 version；使用独立幂等键，成功后保留返回记录。以下给出两笔**可选顺序执行的计划**，不是实测结果。

1. 从 005（一月合成书店，原消费 minor=`"2500"`）登记 2026-02-05 退款，输入金额 `5.00`，minor=`"500"`，资金账户 `合成钱包B`。
   - 二月由空月变为仅退款月：income=`"0"`、grossExpense=`"0"`、refund=`"500"`、netExpense=`"-500"`、surplus=`"500"`、count=`"1"`、hasRecords=true。
   - 二月学习分类 grossExpense=`"0"`、refund=`"500"`、netExpense=`"-500"`；毛额总计为零，不能除零或显示退款为收入。
   - 一月所有期间金额/count 不变；2026 年 income=`"13000"`、grossExpense=`"10300"`、refund=`"500"`、netExpense=`"9800"`、surplus=`"3200"`、count=`"14"`。
2. 在第一笔基础上，从 010（九月合成书店，原消费 minor=`"2000"`）登记 2026-10-02 退款，输入金额 `3.00`，minor=`"300"`，资金账户 `合成钱包A`。
   - 十月变为 income=`"2000"`、grossExpense=`"1800"`、refund=`"300"`、netExpense=`"1500"`、surplus=`"500"`、count=`"5"`。
   - 十月毛额顺序仍是餐饮 `"800"` → 交通 `"600"` → 学习 `"400"`；学习 refund=`"300"`、netExpense=`"100"`。九月所有期间金额/count 不变。
   - 两笔完成后的 2026 年：income=`"13000"`、grossExpense=`"10300"`、refund=`"800"`、netExpense=`"9500"`、surplus=`"3500"`、count=`"15"`。年度学习分类 grossExpense=`"4900"`、refund=`"800"`、netExpense=`"4100"`；年度毛额顺序保持学习 → 餐饮 → 交通，不按退款后净额改成餐饮在前。

退款计入**退款发生月**并继承原消费分类，不回写原月金额，不计收入。若只执行第二笔而未执行第一笔，年度退款仅为 `"300"`，不能使用上述两笔完成后的年度数值。撤销导入、纠错、额外手记等均会改变基线，应另算并留验收证据。

## 实际完成与未完成的核验

- **已运行**：系统 Python 标准库 `csv` + `decimal.Decimal` 读取这份合成 CSV；断言笔数、ID 唯一、两个账户、两种收入分类、三种支出分类、金额两位小数、CNY 与普通收支类型；逐月/全年金额与 count、九个空月、分类毛额排序，以及上表前五组 AND 条件。输出 PASS，进程退出码为 0。另以 Decimal 核验两笔计划退款后的数值，并将文档逐月表与 CSV 对照。文档对照脚本首次因 Decimal 字符串保留 `.00` 与期望整数串不一致而失败；修正临时核验脚本的整数格式化后重跑 PASS（退出码 0），夹具金额未变。只读取合成文件和本文，不连接数据库。
- **未运行**：Go 隔离测试、Go vet/race、客户端测试、Web/Mac 构建、正式 CSV 预览/提交、重复导入、退款 API/UI、Web/Mac 实际操作、重启持久化与分页边界。本任务仅新增夹具和期望文档，完整构建与真实双端验收由父任务负责。
- Decimal 仅为本地人工期望的独立算术复核，不是正式客户端账务逻辑；业务权威仍为现有 Go 的导入、退款及统计实现。上述制作阶段的 UI/API 数值是**待验收期望**，不能仅据此写成实测通过；后续实际结果单列如下。
