# 私有离线升级协调器验证（2026-11-07）

基线 aae3cd9；[设计与范围](../plans/expense-pair-offline-upgrade.md)。所有数据均在临时目录创建或由既有合成测试fixture生成；无真实账本、账号凭据或正常环境路由变更。

## 用例

- 成功：固定源v5→私有协调器提交v6，当前正常Open明确拒绝产物；生成备份仍v5且VerifySnapshot通过。备份恢复新目标并正常Open后，完整逻辑指纹与升级前相等。调用方租约保持；重复升级拒绝，不生成第二备份。
- 拒绝：无租约、版本4、未知关联索引、active及withdrawn非空关联表，均拒绝；前置拒绝不生成备份。
- 失败：snapshot返回错误、manifest损坏、另一有效但错误的v5备份、备份后取消、已有备份目录都保留源版本5（版本4输入仍4）。
- 并发：在源读事务快照建立后，独立非协作写者成功提交DDL，再尝试升级必须失败；测试明确断言该写者确实提交，避免单纯callback错误误判为并发保护成功。
- 字节保真：SQLite TEXT含非法UTF8字节ff与fe，逻辑指纹不相等，避免JSON替换字符导致错误备份被视为相同。

## 审查

第一次独审指出两项P2：只校验备份自洽、不独立绑定源内容，以及缺少提交前备份Sync。增加全schema/全表逻辑指纹核对，并在提交前依次同步数据库、manifest、备份目录、父目录；错误全部拒绝。
