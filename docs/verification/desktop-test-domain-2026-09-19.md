## 实现

- 显式 `MONEE_SERVER_URL` HTTPS 模式与可选公开 CA 文件；错误不回退本机。默认本机发现/进程身份检查不变。
- Java HTTP 引擎独立 SSLContext，保留证书与主机名验证，Ktor/JDK 两层不跟随重定向；打包包含 `java.net.http` 和 `jdk.crypto.ec`。
- 只有精确配置的 origin 走直连，其余委派系统代理；不更改操作系统代理。启动脚本默认独立测试数据与会话作用域。

## 已实测

1. 原 CIO 实现的真实 TLS 反向测试失败：SAN 只有 localhost 时，连接 127.0.0.1 意外成功；已弃用该实现，不沿用先前静态审查的安全结论。
2. 实际 JVM 将测试域名送往系统 Web 代理，握手被终止；系统 DNS 正确解析到测试主机，直接可信 HTTPS 检查成功。加上仅对指定 origin 直连后，同一真实客户端 health 诊断通过。
3. 35 项共享测试通过，含实际平台工厂：可信 CA + 正确域名成功、错误主机名/不可信 CA/无效配置失败、过期 CA 输入拒绝、307/308 不向第二个受信 HTTPS origin 转发合成 Bearer 或 proof。Mock 用例覆盖协议不兼容、网络取消、不回退本机和钥匙串作用域隔离。测试密钥/证书均临时生成并清理。
4. Go 全量 race/vet、Web 生产构建及 Mac 分发构建通过。Web 仅现有资源体积/动态依赖警告。
5. 打包运行时实际含上述两个模块。以独立临时目录及可信公开 CA 启动分发 App，通过原生界面观察到 Google/GitHub 登录页，无服务连接错误。真实域名 health 为原服务 schema 2，只读，没有试写账本。
6. 独立审查无剩余已确认 P1/P2；其打包模块和 HTTPS→HTTPS 重定向测试意见已修复并重跑。未覆盖的代理选择分支小测试为非阻塞建议。
