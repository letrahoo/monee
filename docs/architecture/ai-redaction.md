# 云端 AI 字段投影与脱敏边界（M-26）

当前实现是 `server/internal/redaction` 的纯程序模块。它生成可供检查、将来可用于模型请求的固定 JSON 字节；没有接入网络、供应商、API 或客户端界面，也不会改变入账规则。M-26 尚未完成端到端交付。

## 数据契约

调用方先按账本规则校验并归一化金额、日期、来源及类型，再创建 `Input`。不得把原始账单、`ingestion.Document`、`Record.Raw` 或任意结构直接序列化给模型。`Input` 不提供原始字段透传入口，输出结构只有固定字段。

| 输入 | 云端投影 | 边界 |
| --- | --- | --- |
| 来源记录 ID | `ref`，HMAC 别名 | 必须是稳定的单次来源记录 ID，不能仅用行号；不输出文件名或本地路径 |
| 金额 | `amountMinor`，正整数十进制字符串 | CNY 分，最多 13 位；不使用浮点；非法或不确定金额应留在本地处理 |
| 日期 | `date`，YYYY-MM-DD | 精确到日，舍弃小时分钟须由上游显式完成；拒绝任意自由文本 |
| 币种 | `currency` | 当前仅 CNY，其他币种拒绝 |
| 收支方向 | `direction` | income / expense / unknown；不代表自动入账决定 |
| 来源 | `source` | alipay / wechat / jd / cmb / abc / bank_of_shanghai / icbc / other；这是允许的标签，不表示相应解析器均已实现 |
| 账户名称、卡号 | `accountRef`，HMAC 别名 | 来源 + 原值，私有原值不输出；保留本地同账户关联 |
| 商户或交易对方 | `merchantRef`，HMAC 别名 | 不直接公开名称；可能是个人姓名，不能用正则声称识别干净 |
| 商品说明、备注 | 完全不输出 | 单独标记 `omitted_unstructured_text`；不尝试靠正则或 AI 删除姓名、地址或指令后放行 |
| 订单或流水号 | 固定 `kind` + HMAC `ref` | kind + authority scope + value 构成完整命名空间；不输出原值或 authority scope |
| 原始列、分类自由文本、联系方式、文件名 | 无输出字段 | 不在输入契约中，不允许扩展字段自动透传 |

完整手机号、邮箱、卡号、姓名若藏在账户/商户/标识字段中，只参与本地 HMAC，不出现在投影 JSON 中；备注一律省略。程序不声称识别所有个人信息，也不声称把这些数据变成匿名数据：**精确日期、金额、关联关系和固定来源仍可能具有识别性**。投影结果依旧是敏感的假名化账单数据，后续云端处理需要相应权限、使用目的和预算控制。

现阶段不输出商户可读名称或备注，因此模型能利用的语义有限。将来若增加词典标签，只能从本地审核过的有限词表投影，不应增加“任意文本通过检测即可发送”的通道。

## 稳定关联与隔离

`New(key)` 要求调用方提供至少 32 字节密钥，并复制密钥以避免外部切片变更。生产密钥必须来自安全随机数并安全保管；长度检查不等于熵检查。

别名使用 HMAC-SHA256，输入为 JSON 数组：协议版本、账本 ID、字段域和字段组成部分。数组分帧避免拼接歧义。字段域区分 record、account、merchant、identifier。不同账本或不同密钥生成不同别名；原始账本 ID 不出现在结果中。

允许的标识种类与现有解析器一致：

- `alipay_payment_trace`：仅支付宝来源。
- `wechat_payment_trace`：仅微信来源。
- `merchant_order`：完整商户订单号及其签发方作用域。
- `source_transaction`：标准化来源流水号及其明确作用域。

未知种类、缺少作用域或值均拒绝整个请求。支付宝与微信支付流水即使号码相同也不会形成相同标识。只有同一账本中的 **kind、签发方作用域、原值都相同** 才保留相同别名。现有解析器若生成不同作用域，投影不会自行合并；将来受信任的关联层可以提供已验证、规范化的共同签发方作用域。

该模块不根据同日同金额、商户名称或模型判断生成关联，不接受“已经验证”的布尔标记作为关联依据。相同别名只是证据引用，不能据此自动合并来源记录或重复入账。经济事件判定仍由账本规则和证据校验负责。

## 可检查的实际字节

`Project(ledgerID, inputs)` 返回 `Preview`：

- `Bytes()` 返回不可变内部 JSON 的防御性副本。未来界面展示与供应商适配器必须使用这份投影，而不能从私有 `Input` 重新拼出另一份请求。
- `Treatments()` 返回本地逐条处理说明：记录别名、商户/账户是否假名化、备注是否省略、保留的标识数；没有原始私密字段。
- 任一字段验证失败，整个请求不返回部分 JSON；错误仅含记录序号和固定字段名，不回显私密值。

最大批次 1000 条，单记录最多 16 个标识；字段长度受限。输出包含协议版本 `monee-redaction-v1`。版本/密钥变更会改变关联语义，后续调用方不能混合不同版本的映射。

## 已验证与待集成

合成测试覆盖：姓名/完整卡号/联系方式/备注指令不泄露、精确整数金额、相同输入稳定、账本/字段/密钥隔离、标识命名空间分离、已存在共同商户订单证据保留、未知字段枚举拒绝、无部分输出、字节副本防篡改、错误不回显、重复来源 ID 拒绝。测试不读取用户账单或密钥，也不调用云端模型。

仍需独立完成：

1. 服务端密钥生成、加密存储或系统凭据存储、备份/换机迁移、轮换版本和授权读取，禁止密钥写日志或 Git。
2. 已授权账本证据到 `Input` 的适配，财务字段归一化、最小必要范围选择，以及跨来源签发方规范化的证据规则。
3. 授权 API 和客户端“实际发送字段”检查界面；请求审批、内容摘要绑定及并发修改检测，确保展示与发送一致。
4. 供应商适配、预算、重试、超时、日志过滤、请求/响应存储与删除边界。网络调用不能偷偷追加原始账单。
5. 模型输出的不可信处理、规则校验和待确认队列；不能因为模型声称确定就直接入账。
6. Web / Mac 实际操作验收。这次模块测试不替代未来完整产品链路验证。
