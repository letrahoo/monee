# ai-ledger 参考分析与原生账单接入

2026-09-15。只读分析用户指定的 ai-ledger main，参考提交 e7ee83c。该项目为私有仓库；本文仅记录通用格式和工程结论，不复制私人聚合报告、账号、交易或金额。

## 能拿到什么

仓库包含解析程序、数据模型、规则、测试和聚合文档。真实 CSV/XLSX/PDF、SQLite、逐笔导出和产品快照被 Git 忽略。克隆代码不能恢复原始明细；不能从报告总额生成真实流水。

| 来源 | 源码明确支持的输入 | 对 Monee 的意义 |
| --- | --- | --- |
| 支付宝 | GB18030 CSV，前导说明后出现交易时间表头 | 本轮先实现原生来源提取；同时支持 UTF-8 |
| 支付宝小荷包 | CSV，单独账户与订单结构 | 应保留独立来源账户，避免与支付渠道混用 |
| 微信 | XLSX，表头可能在前 50 行，多个来源账户 | 需要工作表位置、支付流水号及独立账户范围 |
| 京东 | CSV，金额字段可能夹带部分退款说明 | 原价、退款金额、净额分开，不在解析阶段直接相减 |
| 淘宝 | XLSX 订单 | 属于购买证据；关闭订单不能转换为收入 |
| 招商储蓄 | PDF | 需要页码/行定位与金额符号验证，不能按整个来源排除 |
| 招商／农业信用卡 | 邮件 HTML/PDF | 交易日期和记账日期分开；邮件与附件可能是重复证据 |
| 上海／工商银行、独立白条账单 | 未找到专用解析器或原始样本 | 不因文档提到资金账户就宣称格式已支持 |

这些是源码识别到的格式，不是当前原始文件完整盘点或真实账单验收结果。

## 沿用与修正

沿用原文件归档、文件指纹、导入批次、原始记录、正式交易及去重关联分离的思路。消费来源、支付渠道、资金账户分开建模，正式记录可以关联多个证据。

需要修正的旧实现：

- 金额经过 float 转换和误差阈值比较。Monee 提取阶段保留十进制字符串，正式账本使用整数分，拒绝额外精度。
- 支付流水号缺失时使用商家订单号替代，之后按统一 order_id 跨来源分组。Monee 将标识类型和账户/发行方范围分开，缺失不补造。
- 部分京东退款在解析时直接扣减，关闭淘宝订单曾映射为收入。原始消费、退款和关闭状态应独立保留，再由业务规则处理。
- 同额、相近日、渠道及商户相似度用于自动去重。此类结果先作为候选证据，不能仅靠旧置信度或同日同额自动合并。
- 无法解码字符替换、非日期行跳过会掩盖丢行。新解析器遇到未知结构明确报错，并保存原文件用于复核。

## 本轮开发边界

新增 Go `ingestion.ParseAlipayCSV` 和 `inspect-bill` 私有解析命令。支持明确的支付宝交易明细表头、UTF-8/BOM/GB18030、前导说明、带引号的多行字段；保留原文件指纹、物理行、原始列（含状态、付款方式及未知列）、原始收支/金额字符串及分类型订单标识。

来源账户别名必须显式提供，银行卡付款方式不作为支付宝账户身份。商家订单号的商户名称范围只用于保存证据，不能据此认定跨来源的稳定商户身份。

命令仅创建新的私有目录，写入原始 CSV、解析 JSON 和说明。格式错误时返回失败，同时保留问题与源文件；不覆盖已有目录。输出含私有字段，不能作为云端脱敏结果。未知页尾会显式报错，不能把解析到部分行当成完整成功。

```sh
go -C server run ./cmd/inspect-bill \
  -source "$ALIPAY_CSV" -account alipay-primary -out "$PRIVATE_INSPECTION_DIR"
```

这是可执行的来源解析能力，**尚未接入 Web/Mac 导入入口，也没有写入账本**。原生方向/状态没有转换成可入账类型；标准 CSV 和旧快照迁移继续使用原有路径。后续接持久化、错误/疑问展示、来源关联和财务校验，再通过两端 UI 验收后开放原生导入。

## 验证要求

合成用例覆盖双编码、原字节哈希、多行定位、尾逗号、重复/缺失/混用表头、未知结构、大小/行数限制、账户隔离、两种标识不混用、退款及额外小数精度不被改写。命令验证私有文件权限、禁止覆盖、错误证据保留。没有原始账单，因此不宣称真实支付宝文件通过验收。
