# 统一导入契约：第一批实现

2026-09-15。关联产品任务 M-02（来源模型）、M-04（批次追溯）。

## 本次实现

`server/internal/ingestion` 负责提取来源证据，不依赖数据库或模型服务，也无入账权限。标准 CSV 解析已接入此层；原有 Go 账本层继续验证金额、币种、日期、交易类型、去重、成员权限和事务。

- Document：原文件字节的 SHA-256、解析器名称与版本、记录和结构错误。BOM 和换行改变会产生不同文件哈希，但不改变原有交易去重规则。
- Record：文件内逻辑序号、物理起始行、原始字段值、类型化外部标识。多行备注不会破坏物理行号。
- Identifier：kind / scope / value。内部匹配键包含账本范围；标准 CSV 使用来源和账户构成 scope。原生支付流水号、商户订单号不得共用未经验证的命名空间。缺少标识不凭金额构造交易身份。
- 金额保留十进制字符串，解析层不四舍五入，不把退款或转账转换为普通收支。结构错误和业务校验错误仍会阻止当前 CSV 整批保存/提交。

MatchKey 是内部匹配原语，**不是脱敏接口**，目前不替换已部署的 identity_key，避免破坏历史去重。原始字段和普通哈希不得直接传给云端 AI。M-26 的程序脱敏是后续独立边界。

## 可读取的批次证据

- `GET /api/v1/imports?page=1`：当前账本已保存的预览和已提交批次，每页 50 条，按创建时间、ID 倒序。
- `GET /api/v1/imports/{id}`：批次摘要、保存的预览和已提交的 source_records。每条包括来源行号、正式交易 ID、added / duplicate 处置及当时规范化的记录快照。

以上 API 逐请求验证系统准入和账本成员资格；只读成员可以读取。查询别的账本里的批次 ID 返回 404；被移除的成员返回 403。查询使用同一数据库快照，响应禁止缓存，不暴露 raw_csv 或原始文件。规范化字段仍然是账本私有数据。

相同交易在不同文件中出现时，现有 source_records 会保存每个批次的来源证据，交易本身不重复增加。重新提交同一批次不会重复增加证据。详情中的预览状态反映该批次已提交；记录快照不宣称是后续编辑后的实时交易。

## 尚未实现的边界

本次没有 schema 升级。Document / Record 是解析契约，不是新增持久化实体；尚未落地独立来源文档、未入账记录、类型化关联和关联修订数据库。错误文件当前不保存为批次，因此不在导入历史中；不能声称已经覆盖全部失败/待核实记录的持久化。

未接入支付宝、微信或银行原始格式；旧快照迁移输出的标准 CSV 继续兼容。AI、自动入账、退款、转账、还款、撤销和历史 UI 不在本次代码变更内。它们按 Notion 的交付批次继续推进，不因基础 API 完成而标为已交付。

## 后续切片

1. 盘点实际格式；由来源适配器输出本契约，不复制账本规则。
2. 在版本化备份和迁移测试保护下，将文档、来源出现记录和证据关联独立持久化，保留全部原始输入与旧 ID。
3. 构建导入历史/处理状态 UI，再加入疑问处理与自动提交策略。

## 验证

合成测试覆盖多行字段、原始字节指纹、结构错误、大小/行数限制、金额及类型不被解析器篡改、标识命名空间和账本隔离；现有全量测试覆盖标准导入与旧快照迁移。历史接口验证重复来源关联、重试幂等、未提交状态、分页、只读读取、跨账本拒绝和撤权。
