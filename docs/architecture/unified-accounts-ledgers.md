# 统一账号与账本授权

## 已确认的产品规则

- 保留系统准入白名单；获准用户可以创建自己的账本。
- 一个产品账号绑定多个外部身份。Google / GitHub 已实现，飞书本期不启用。
- 账本角色为所有者、可编辑、只读；只有所有者管理成员。平台超管没有隐含的账本读取权。
- 邀请填写对方 Monee 用户 UUID，由对方接受；邀请本身不授予访问权，不发送邮箱或聊天消息。
- 已分别注册的账号可在验证另一个身份后明确确认合并。保留双方账本；同账本取较高角色，原账号会话失效，原始操作人仍可追溯。
- 当前电脑进行本地验证；未来阿里云部署需单独完成 HTTPS、远程服务地址、会话 cookie、运维等改造。本次没有上线云端。

## 持久化模型

继续采用 SQLite、整数分、稳定 UUID、Go 业务规则和 KMP 共享 UI。正式文件为数据目录中的 `application.db`，原来的 `monee.db` 与 `auth.db` 在升级时保留。

| 表 | 含义 |
| --- | --- |
| app_users | 产品用户 UUID、昵称、状态和 merged_into；合并后保留历史用户 |
| users | 兼容旧版的提供方资料表，以 provider / subject 为键，不再代表产品用户 |
| user_identities | 外部身份 → 产品用户，一条外部身份只能属于一个产品用户 |
| user_access | 产品账号级准入和平台角色、版本；所有登录渠道共享 |
| allowlist | 预设外部身份准入邀请；不再是账本成员列表 |
| sessions | 记录本次提供方身份；通过 user_identities 解析到统一用户，合并/解绑撤销相应会话 |
| ledgers | 独立账本 UUID、名称、币种、版本、设备 ID |
| ledger_members | 账本与用户的成员关系、角色与版本；唯一索引保证每本至多一位所有者 |
| ledger_invitations | 待确认邀请，接受/拒绝后移出待处理表，结果保留审计 |
| ledger_audit | 创建账本、邀请、接受/拒绝、成员变更的不可变记录 |
| transactions / imports | ledger_id 隔离，并保存 created_by；存量未知操作人保持 NULL |
| change_log | 保留原版本与稳定标识，新增 actor_id |
| idempotency | 主键改为 ledger_id + key，避免跨账本复用键导致串账 |

`accounts` 仍然只表示资金/分类账户，不能用来表示登录账号。账本资金账户继续为待核实 clearing 类型，不宣称真实资产余额。

## 授权边界

API 必须先验证会话与系统准入，再按请求账本验证成员角色。`X-Monee-Ledger` 是选择参数，不是授权凭证。客户端每次账本请求都显式携带它；兼容旧客户端时，仅在用户恰好有一个成员账本的情况下允许省略。

读取统计需成员权限；创建交易、保存预览和确认导入需要所有者或可编辑。提交事务中再次检查权限，即使预览后被移除或降为只读也不能提交。创建账本、接受邀请和改变成员均在事务中完成。批次 ID、幂等键、来源身份、统计和查询均在账本范围内操作。

新客户端会在切换账本时重建账本状态；失去账本权限或读取失败时清除旧账本展示。后台刷新获取新的角色，只读角色不显示可用写入操作；后端仍是最终授权者。

系统准入按统一用户停用，不会因换一种登录渠道而恢复；重新登录也不能把停用账号自动启用。初始超管继续来自私有配置，不采用首个注册者成为超管的规则。

## 绑定、合并和解绑

绑定复用 Provider 接口、state、PKCE、浏览器绑定 cookie 和原生 proof。`auth/start` 增加 `intent=link`，必须由已有获准会话发起。回调重新核验发起会话仍有效，不能把另一个身份的登录结果替换成当前会话。

尚未注册的身份可以绑定到当前用户；已注册身份产生 10 分钟内有效的待合并项，必须由原发起会话再次确认。不能仅按相同邮箱或昵称合并。合并保存双方身份与账本关系；对于重叠关系保留所有者，其次可编辑，最后只读。原用户标记 merged，历史交易创建人和审计 actor 不改写。来源账号旧会话全部撤销。

解绑只允许操作当前用户拥有的身份，撤销该渠道会话；最后一种登录方式和初始超管的受保护身份不能解绑。产品准入属于统一账号，不依赖仍绑定哪个渠道。

## 飞书扩展边界

本期不显示可用飞书登录按钮，也不把飞书凭据加入配置。后续通过现有 `Provider` 接口实现授权 URL 与授权码交换，注册到 `NewProviders`，补配置验证、身份格式与准入选择器、客户端渠道名称及对应测试即可。回调同源例外仅接受实际注册的提供方。

飞书适配时必须明确身份 ID 的应用/租户作用域，将作用域纳入规范化 subject，避免不同应用的 ID 被误认成同一人；不得用显示名、邮箱或手机号自动合并。当前 schema 中的旧准入渠道约束也需在该适配迁移中扩展。此次“预留”是接口与模型边界，不代表已实现或实测飞书认证。

## 数据库升级与备份

服务持有数据目录锁后，在旁路临时数据库完成旧账本与认证数据的合并。升级前通过 SQLite 一致性快照保存两个旧库，并生成版本、schema 和 SHA-256 清单；快照及恢复均执行 integrity_check / foreign_key_check。全部迁移成功后才将临时数据库发布为 `application.db`。原文件不删除，旧会话不迁移，用户重新登录。

旧共享账本不会自动授权给全部白名单用户或首个登录者；已有账本数据与 ID 保留为未分配状态，需要明确其所有者后再做单独归属迁移。本次已批准的历史 CSV 导入到用户亲自登录后创建的指定账本，不使用旧共享库默认授权。

版本化快照与恢复命令（输出必须是新目录或新文件）：

```sh
go -C server run ./cmd/database-backup -source "$MONEE_DATABASE" -out "$NEW_BACKUP_DIR"
go -C server run ./cmd/database-backup -restore "$BACKUP_DIR" -out "$NEW_DATABASE_FILE"
```

快照可读取 WAL 中已提交的数据；恢复不会覆盖现有文件。将恢复文件用于应用前应停止服务、保留现有数据库并完成一致性核对。OAuth 配置不包含在数据库备份中，仍需单独保存为私有文件。上述命令不等于云端同步或灾备高可用。

## API 与界面

正式机器契约见 `api/openapi.yaml`。新增：

- `/api/v1/auth/account`：账号详情、昵称；`/unlink`、`/merge`：解绑及确认合并。
- `/api/v1/admin/users`：已注册统一账号与准入状态；`/{id}`：启用/停用。
- `/api/v1/ledgers`：我的账本、创建账本。
- `/api/v1/ledgers/{ledger}/members` 与 `/{user}`：成员列表、角色修改与移除。
- `/api/v1/ledgers/{ledger}/invitations`：邀请；`/api/v1/invitations` 与 `/{id}/respond`：收到的邀请与响应。

Web / Mac 共用账号设置、账本选择、新建账本、邀请确认与成员管理 UI。邀请所需的用户 UUID 可以复制。原生登录继续通过系统浏览器和 proof 领取会话，不复制浏览器令牌给 Mac。

## 验证与边界

自动测试覆盖：备份恢复、篡改拒绝、旧双库迁移及重启、旧稳定 ID 保留、旧会话不迁移、邮箱不自动合并、绑定要求登录、原会话注销后绑定失败、合并需二次确认且不可重放、角色合并与旧会话撤销、多渠道统一停用、最后身份保护、跨账本访问拒绝、超管无隐含数据权、邀请接受前无权、第三方不能接受邀请、只读不能写入、预览后撤权不能提交、跨账本批次与幂等键隔离。

实际验收记录在开发交接中维护；合成提供方只存在 `_test.go`，生产入口没有免登录模式。云端部署、多设备同步、完整退款/转账模型、账本所有权转让和自助销户不在本期实现范围。
