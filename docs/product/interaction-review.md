# 交互整理

本轮依据页面实现和用户反馈整理。浏览器工具无法通过管理员策略校验，未进行实际浏览器点击与截图验收；以下是已实现的行为，不代表已完成视觉验收。

- 账单页保留账本、账号入口和记账操作；准入管理、退出登录放在工作区，减少首页按钮干扰。
- 主内容居中并限制最大宽度，管理页采用统一背景、间距和卡片。主要导航和账本操作可换行。
- 从账号设置或账本列表可直接返回刚查看的账本。
- 个人资料、登录方式、待处理邀请、账本和成员管理分别成组。账号 ID 按需展开；新建账本默认折叠，首次使用时展开。
- 首次加载使用进度提示，失败提供重试，避免提前显示空账本说明。首次加载有待确认合并时优先展示账号设置。
- 已绑定渠道不再提供绑定按钮。昵称为空或未变化时不提交保存。移除成员须确认影响。
- 导入、手动记账可显式收起，已输入的内容在当前账单页内保留；收入和支出显示正负方向，分页显示总页数。只读账本空状态不提示写入操作。

后续人工视觉验收关注窄窗口换行、键盘焦点、长名称、导入预览和成员确认操作。构建验证不能替代这些检查。

## Mac 原生窗口验收补充

已通过原生窗口实际确认：应用启动显示登录页；点击 GitHub 登录按钮后才打开浏览器并进入等待状态；登录后可访问工作区、返回 letra 账本、选择历史月份并加载账单及统计。启动逻辑仅查询已有会话，不自动发起 OAuth；后续验收不得在未说明的情况下重复点击登录。

实际发现支出明细重复显示负号，原因是已带符号的金额又拼接了方向符号；现已统一格式化并补充正数、负数、零及最小整数回归测试。

搜索验收时原生自动化先后出现剪贴板读取超时与窗口不可用，未确认输入结果。搜索、表单和完整导航验收仍未完成，不能标记为全部通过。
